# Shopee Agni destination availability

The Shopee Agni Item & Store table shows products not found in the saved TikTok Agni or Gitashop catalogs. Missing destinations receive an amber product row and an explicit destination label. Products missing both destinations come first, followed by products missing one, before the existing missing-SKU and selected ordering. Ordering applies to the entire filtered catalog before its existing 20-row pagination, so the first page starts with missing products.

Availability is read-only and based on saved catalogs, not live remote verification. Any corresponding target variant proves product presence; incomplete variant coverage is outside this feature. Match by source-owned INT item prefix, an exact source SKU owned by only one source product, or explicit marketplace/legacy links whose target product still exists in the correct saved catalog. An exact INT SKU naming another source item is contradictory evidence and remains unknown unless independent evidence proves presence. Deleted cache rows and different accounts do not prove presence. Unavailable source identity or empty/unavailable destination caches produce an unknown label, never a missing highlight. The selected filters remain applicable. Stock, Stock Master, mappings, and remote catalogs are not mutated.

A dedicated backend service loads each target catalog once and builds indexes for all products. The existing Shopee items API returns destination availability only for the primary Agni account. A frontend helper generates labels and priority, and the table uses these before slicing pages. Tests cover account isolation, removed rows, stale links, missing identities/caches, exact and prefix matches, duplicate source SKUs, and whole-catalog pagination priority. Build assets are published to backend/public and checked over HTTP.

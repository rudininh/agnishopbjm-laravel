# Create a missing TikTok product from the stock hub

Approved by the operator on 2026-10-05: the primary Shopee Agni rows at `/sinkronisasi-stok` gain a **Buat di TikTok** action when TikTok destination presence is missing. One action copies the entire fresh Shopee product: title, description, main/variant images, every variant, seller SKU, displayed selling price, and available stock. Only TikTok Agni is a creation destination. Shopee Gita and the source inventory are untouched; Stock Master quantities are never changed.

Saved catalog absence is only a hint. The server proves source-account ownership, validates a fresh complete source product, and scans the live TikTok catalog (including inactive/under-review products) before creation. Existing linked products, source-owned INT prefixes, matching seller SKUs, or ambiguous same-title candidates block new creation. Empty/duplicate seller SKUs, conflicting INT ownership, missing/invalid price or stock, incomplete pagination, unavailable images, and unsupported attributes produce an actionable blocked result before product submission. Existing products are never edited by this action.

The backend uses dedicated focused services and account-scoped signed transport, rather than adding another large workflow to OmnichannelController. Persist a source-product/account run with request identity, scan/upload progress, payload, sanitized result, returned product/SKU IDs, and a permanent submission-attempt marker. Serialize source-product creation and coordinate with the existing catalog/marketplace mutation lease. A submitted or uncertain request is never resubmitted automatically. A repeated request or reload recovers the existing run and verifies the remote product when an ID is known. Explicit rejection is distinguishable from an unknown transport outcome. Only proven pre-submission failures or explicit marketplace rejection allow a new attempt.

Use bounded step endpoints so the browser can show progress during catalog scan and image upload without relying on a single long HTTP request. A safe GET reads current run status. One click starts/resumes the workflow and continues steps while the page is mounted. The browser retains only run identifiers. Creation progress disables conflicting actions and account changes. A lost response recovers by run identity; it must never start another creation merely because a network call failed.

Read source data from Shopee freshly. Preserve nonempty valid seller SKUs; require repair through the existing SKU tools when missing or contradictory. Keep price strings in IDR and zero stock distinct from missing stock. TikTok images must be uploaded to TikTok URI assets before submission, including variant images. Obtain category/warehouse/package context from validated configured mappings and fresh source shipping data. If required context cannot be inferred, display a compact completion form for those fields; do not silently choose a category for unrelated products. The TikTok payload uses the real API create contract, including category, package weight, structured main images, sales attributes, per-SKU price/inventory, and warehouse.

After creation acceptance, read back the returned product and verify all expected SKU identities and variant coverage. Cache proven target identities and prices/stock/images in the existing TikTok catalog shape, and attach account-scoped mappings only where existing Stock Master source ownership is unique. Do not invent Stock Master rows or overwrite conflicting mappings. Update the destination indicator after remote acceptance with a persistent run result; report under-review status separately from live publication. If readback fails, retain the ID and show **Terkirim, belum terverifikasi**, with check-status recovery and no create replay.

Validation includes PHPUnit HTTP-faked integration tests for complete multi-variant payloads, account isolation, pagination, duplicates, zero stock, missing context, image failures, accepted/under-review/readback results, rejection, uncertain responses, concurrency, replay, and unchanged source/Stock Master quantities. Frontend behavior tests cover eligibility, single-click orchestration, progress, missing context, recovery, no replay and disabled conflicting actions. Publish the Vite build to backend/public and verify the actual Laragon page and referenced assets. Live creation is initiated by the operator's product button; automated verification uses fakes and read-only live calls.
